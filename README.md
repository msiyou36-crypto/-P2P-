# سجل حوالات P2P — دليل المطوّر

تطبيق ويب عربي (RTL، داكن) لمتابعة سجل حساب Binance: طلبات P2P (بيع/شراء USDT)، الإيداع والسحب،
Binance Pay، التحويل بين العملات، والسوق الفوري — مع عمود «الباقي من USDT» يعمل ككشف حساب.
يعمل بـ **Node.js فقط بلا أي حزمة خارجية** (لا `npm install`)، ويُنشر كخدمة واحدة لكل حساب.

للمستخدم النهائي: [اقرأني.md](اقرأني.md). للنشر: [نشر-على-الإنترنت.md](نشر-على-الإنترنت.md) (Render + Supabase)
و[نشر-على-alwaysdata.md](نشر-على-alwaysdata.md).

## الشجرة

```
server.js              الخادم: الحالة، الدمج، المزامنة، مسارات HTTP (فهرسٌ في أول الملف)
lib/store.js           التخزين: ملفات JSON محليًا أو جدول kv في Supabase
lib/binance.js         عميل Binance: التوقيع، بوّابة الحظر، حدود الوزن، fetchC2C، fetchPay
lib/normalize.js       توحيد السجلّات (طلب/حوالة) وقراءة ملف التصدير
lib/auth.js            كلمات السر (scrypt) والجلسات والأدوار
lib/xlsxread.js        قراءة Excel/CSV بلا مكتبة (للاستعادة من ملف تصدير)
public/index.html      الصفحة الوحيدة (شاشة الدخول + التطبيق + النوافذ)
public/style.css       التنسيقات؛ لون كل سستم تحت :root[data-account]
public/js/*.js         الواجهة مقسّمة بالوظيفة (الترتيب والشرح في js/core.js)
public/xlsx.js         مولّد Excel بلا مكتبة · public/glitter.js خلفية النجوم
test/                  اختبارات تشغّل الخادم الحقيقي على منصّة وهمية (npm test)
test/dev-server.js     خادم معاينة ببيانات عيّنة ومنصّة وهمية (node test/dev-server.js)
```

## التشغيل

| الأمر | ماذا يفعل |
|---|---|
| `node server.js` أو `تشغيل.bat` | محليًا على `http://127.0.0.1:3131` بالتخزين في `data/` |
| `node test/dev-server.js` | معاينة على `:3147` ببيانات عيّنة ومنصّة وهمية (مسؤول `test1234`) |
| `npm test` | كل الاختبارات (نحو ٤ دقائق لأن الجلب يُحاكي فواصل المنصة) |
| `node test/run.js core` | ملف اختبار بعينه |

### متغيّرات البيئة

| المتغيّر | المعنى |
|---|---|
| `PORT`, `HOST` | المنفذ والعنوان؛ مع `PORT` يُستمع على كل الواجهات (وتُقبل `ALWAYSDATA_HTTPD_PORT/IP`) |
| `ACCOUNT` | `p2p` أو `p3p`: يقفل النسخة على حساب واحد (وضع النشر). بدونه يُقرأ الحساب من `config.active` |
| `SUPABASE_URL`, `SUPABASE_KEY` | التخزين في Supabase (مفتاح service_role) بدل الملفات |
| `DATA_DIR` | مجلد التخزين المحلي (الافتراضي `data/`) — تستعمله الاختبارات |
| `ADMIN_PASSWORD`, `USER_PASSWORD`, `USER2_PASSWORD` | كلمات السر عند أول تشغيل فقط (لا تُغيَّر إن كانت مضبوطة) |

## البنية

**حسابان، سستمان.** الحسابان `p2p` و`p3p` لكلٍّ مفاتيحه وبياناته. في النشر تعمل نسخةٌ لكل حساب
بمتغيّر `ACCOUNT`، على قاعدة Supabase خاصة به، وبلونه (ذهبي لـP3P، برغندي لـP2P). الخادم يكتب
لون السستم وعنوانه ووسوم Open Graph في الصفحة نفسها (`renderIndex`) فتراه معاينات الروابط.

**التخزين مفتاح ← قيمة** (ملف لكل مفتاح، أو صفّ في جدول `kv`):

| المفتاح | المحتوى |
|---|---|
| `orders__X`, `transfers__X` | الطلبات والحوالات مفهرسةً بمعرّفها |
| `config__X` (محليًا `config`) | الإعدادات، مفاتيح API، كلمات السر المشفّرة، حصّة المزامنة |
| `gone__orders__X`, `gone__transfers__X` | مقابر المحذوف |
| `balsnap__X` | لقطات الرصيد اليومية · `trash__X` سلّة آخر حذف من أداة الفحص |
| `loginlog__X`, `syncusage__X` | سجل الدخول وعدّاد حصّة المزامنة |
| `maintenance__<host>` | وضع الصيانة لكل نطاق |

**الدمج بين النسخ.** كل نسخة تحمل السجل في ذاكرتها وتكتبه كاملًا عند الحفظ، فقبل كل حفظ تُقرأ
القيمة المخزَّنة وتُدمج: ما ليس في الذاكرة يُضاف، وحقول التعليق (`ANNOT` في server.js: ملاحظة،
إشاري، تعديل سعر/مبلغ، تسمية شبكة، مرساة، أرشفة، تثبيت) تُؤخذ من المخزَّن إلا ما عُدّل هنا ولمّا
يُحفظ (`dirty`). الحذف يُقيَّد في **مقبرة** فلا تُعيده نسخةٌ أخرى، وما أرجعته المنصة من جديد يخرج
من المقبرة (`fresh`).

**نموذج البيانات** (الشكل الكامل في `lib/normalize.js`):

- الطلب: `orderNumber, tradeType SELL|BUY, amount, totalPrice, unitPrice, commission, counterPart,
  orderStatus, createTime, source binance|manual|import` + حقول التعليق.
- الحوالة: `id, kind, coin, network, amount, fee, status, time, …`؛ `kind` واحد من
  `deposit | withdraw | pay-in | pay-out | convert-in | convert-out | spot-buy | spot-sell`.
- الأوقات بالمللي ثانية UTC. **اليوم المحاسبي** يبدأ الساعة ٢ ليلًا بتوقيت ليبيا (UTC+2)، أي منتصف
  ليل UTC — في الخادم (`dayStartMs`) والواجهة (`bizDayStart`).

## واجهة HTTP

الصلاحيات: `public` بلا دخول · `login` أي دور · `annotate` المسؤول و«مستخدم 2» · `admin` المسؤول.
الجلسة رمزٌ في ترويسة `X-Auth-Token` (يُمسح عند إعادة التشغيل). التعريف في `server.js` بـ `route(...)`.

| المسار | الصلاحية | الوظيفة |
|---|---|---|
| `GET /api/maintenance` · `POST` | public · admin | حالة الصيانة لهذا النطاق |
| `GET /api/auth/status` | public | هل أُعدّ النظام، والحساب المقفول |
| `POST /api/auth/setup` · `login` · `logout` | public | الإعداد الأول والدخول والخروج |
| `POST /api/auth/password` · `GET /api/auth/log` | admin | تغيير كلمات السر · سجل الدخول (مع المزامنات والفحوص) |
| `GET /api/account` · `GET/POST /api/settings` | login · login/admin | الحساب · الإعدادات (المفتاح مُقنَّع) |
| `GET /api/orders` · `GET /api/transfers` | login | السجل كاملًا |
| `POST /api/orders` · `DELETE /api/orders?id=` · `POST /api/orders/bulk` | admin | إضافة يدوية · حذف (مقبرة) · استيراد دفعة |
| `POST /api/orders/clear` · `POST /api/transfers/clear` | admin | مسح الكل |
| `POST /api/orders/annotate` · `POST /api/transfers/annotate` | annotate | تعليقات الصفّ (ما يمسّ الدفتر كلّه للمسؤول وحده) |
| `GET /api/balance` · `GET /api/balance/snapshots` | login | الرصيد (الفوري + التمويل) ولقطة اليوم · اللقطات |
| `POST /api/balance/freeze` · `unfreeze` | login | تثبيت «الباقي» على الصفوف · إلغاؤه |
| `POST /api/sync {kinds}` (NDJSON) · `GET /api/sync/quota` | login | المزامنة للأنواع المختارة (بلا قائمة = الكل) · الحصّة وثواني الحظر الباقية |
| `POST /api/sync/day {day}` | admin | جلب يوم محاسبي واحد بكل أنواعه |
| `GET /api/diag/p2p?days=` · `GET /api/diag/whoami` | admin | ما تُرجعه المنصة مقابل المحفوظ · UID صاحب المفتاح |
| `POST /api/diag/foreign-ops` (NDJSON) · `/delete` · `/undo` | admin | فحص ما لا يُرجعه المفتاح · حذفه · استرجاعه |
| `POST /api/restore/preview` (ملف خام) · `/apply` | admin | الاستعادة من ملف تصدير |
| `POST /api/archive/before {before, undo}` | admin | أرشفة كل ما قبل تاريخ / إرجاعه |
| `GET/DELETE /api/system/foreign` | admin | بيانات الحساب الآخر في قاعدة هذا السستم (المقفول فقط) |

البثّ (NDJSON): سطر JSON لكل حدث `{msg, pct}`، ثم `{done: true, …}` أو `{error}`.

**المزامنة الانتقائية.** زرّ المزامنة يفتح نافذةً بمربّعات (`public/js/sync.js`): `p2p`، `deposit`،
`withdraw`، `pay`، `convert`، `spot`، و`balance` (تحديث بطاقة الرصيد بعدها، في الواجهة وحدها). تُرسَل
الأنواع المختارة في `kinds` ويُجلب كلٌّ من نقطته وحدها؛ والاختيار يُحفظ في المتصفح. لكل نوعٍ وقتُ آخر
مزامنة (`lastSyncBy` في إعدادات الحساب، ويُعيده `GET /api/settings`). ترتيب الجلب لا يهمّ: السجلّ يُحفظ
بوقته في المنصة فيقع في مكانه من الجدول، وما ثُبِّت من «الباقي» بعد عمليةٍ وصلت متأخرة يُكشف ويُعاد حسابه
(`allowHeal` بعد كل جلب).

## نقاط Binance وما تعلّمناه منها

كلها بمفتاح **قراءة فقط**، والطلبات موقّعة HMAC-SHA256 (`lib/binance.js`).

| النقطة | الحدود | المعالجة |
|---|---|---|
| `GET /sapi/v1/c2c/orderMatch/listUserOrderHistory` | نافذة ≤ ٣٠ يومًا؛ **الصفحة ٥٠ صفًّا فعليًا** (الوثائق تقول ١٠٠)، والترقيم لا يُعوَّل عليه | `fetchC2C`: سقف الصفحة يُتعلَّم من أكبر صفحة وردت؛ كل صفحة تبلغه تُعدّ مبتورة فتُطلب التالية أو تُشطر النافذة نصفين حتى تعود الصفحة ناقصة. رصيد طلبات مشترك لكل عملية، والأحدث أولًا |
| `GET /sapi/v1/pay/transactions` | ١٠٠ سجل بلا ترقيم، وزن ٣٠٠٠ على الحساب | `fetchPay`: النافذة الممتلئة تُشطر؛ ٣ ثوانٍ بين الطلبات |
| `GET /sapi/v1/capital/withdraw/history` | وزن ١٨٠٠٠ على الحساب | تمهّل بعد كل طلب (`coolIfHeavy`) |
| `deposit/hisrec`, `convert/tradeFlow`, `api/v3/myTrades` | نوافذ ٩٠/٣٠ يومًا، ألف سجل | طلب لكل نافذة |
| `get-funding-asset` + `getUserAsset` | — | الرصيد = المحفظتان معًا |

**الحظر.** الحدود على **عنوان IP** لا على الحساب؛ في استضافة مشتركة (Render) يتشارك العنوانَ كلُّ
العملاء فيُحظر بسبب غيرك. بعد أول `429/418` تُغلق البوّابة كلَّ طلب إلى المنصة من كل المستخدمين حتى
ينقضي `Retry-After` (أو ٣٠ دقيقة لـ418)، والمزامنة تُرفض قبل خصم الحصّة، ويُقفل زرّها عند الجميع
(`blockedFor`). الترويستان `x-sapi-used-uid-weight-1m` و`x-sapi-used-ip-weight-1m` تُقرآن للتمهّل
قبل بلوغ الحدّ.

## أشكال عرض العمليات (`public/js/views.js`)

أربعة أشكال لنفس القائمة المفلترة (`state.ledger`) بصفحاتها وفرزها، يختارها المستخدم من أزرارٍ بجانب
عنوان «العمليات» ويُحفظ اختياره في المتصفح (`p2pView`):

| الشكل | ما يعرضه |
|---|---|
| `table` جدول | الجدول الكامل بكل خاناته القابلة للتحرير (الافتراضي) |
| `daily` يومي | الجدول نفسه مجمَّعًا بالأيام المحاسبية، فوق كل يومٍ ملخّصه: العدد، البيع، المقبوضات، متوسط السعر، الشراء، الإيداع والسحب، والباقي آخر اليوم (مرتّبٌ بالتاريخ دائمًا) |
| `cards` بطاقات | بطاقة لكل عملية على نمط بطاقات الطلبات في تطبيق Binance، فيها المبلغ والسعر والإشاري والملاحظة قابلةً للتعديل — الأنسب للهاتف |
| `tiles` مربعات | مربّعات صغيرة متراصّة لمسح يومٍ مزدحم بنظرة؛ النقر يفتح التفاصيل |

البطاقات والمربعات تُجمَّع بالأيام أيضًا حين يكون الترتيب بالتاريخ، ولها قائمة «ترتيب» بدل رؤوس الأعمدة.
ملخّص اليوم يُحسب من القائمة كلّها لا من الصفحة وحدها، واليوم الذي يبدأ في صفحةٍ سابقة يُعلَّم «(تابع)».

## عمود «الباقي من USDT» (`public/js/balance.js`)

سلسلة تراكمية لكل العمليات المكتملة بالـUSDT بترتيب زمني، تُزاح كلّها لتطابق **مرساةً** موثوقة:
دبّوس المستخدم على صفٍّ (`balanceAt`/`zeroPoint`) — وكل دبّوس يُحترم —، ثم أحدث صفٍّ مثبَّت
(`balAfter`)، ثم أحدث لقطة رصيد يومية مستقرّة، ثم الرصيد الحالي. السلسلة تنقطع عند أول رصيد سالب
(مستحيل) فيُترك ما بعده «—» ويُسمّى الدخل المفقود. ما اكتمل وأكّدته قراءة رصيد يُثبَّت في الخادم مرّةً
واحدة؛ ومثبَّتٌ لا يفسّره الدفتر يُمسح ويُعاد حسابه تلقائيًا (`healFrozen`).

والخادم الحقيقي على مجلد مؤقت (`DATA_DIR`). الملفات:

- `core.test.js`: الدخول والصلاحيات، الطلبات والتعليقات، الاستيراد، الحذف والمقابر بعد إعادة التشغيل،
  المزامنة والحصّة، التثبيت، الأرشفة، جلب يوم، فحص الدخيل وسلّة المحذوف، الاستعادة من ملف، الصيانة، سجل الدخول.

- `c2c-modes.test.js`: جلب الطلبات في خمسة أنماط للنقطة وبحجمَي صفحة ٥٠ و١٠٠.

## قرارات وقيود تستحق المعرفة

- **بلا حزم** عمدًا: النشر `node server.js` فقط، والواجهة ملفات ثابتة بلا بناء.
- الملفات في `public/js` تتشارك النطاق العام وتُحمَّل بالترتيب المذكور في `index.html`؛ أي ملف جديد
  يُضاف هناك قبل `main.js`.
- المنصة لا تُرجع طلبات P2P الأقدم من نحو ٦ أشهر؛ لذلك يُحسب «الباقي» على آخر ٩٠ يومًا (أو إلى أقدم دبّوس).
- الاستيراد (`/api/orders/bulk`) **يحدّث** الصفّ الموجود من الملف (حالة، سعر…) مع حفظ تعليقاته؛ الإضافة
  اليدوية لا تكتب فوق صفٍّ جاء من المنصة.
- Render المجاني يُنيّم الخدمة بعد خمول؛ الجلسات في الذاكرة فيُعاد الدخول بعد كل إعادة تشغيل.
- الأرشفة إخفاءٌ من الجدول ومن «الباقي» لا حذف؛ الحذف يُقبر ولا يعود إلا بدليل من المنصة أو استعادة.
- عند التنظيف (أكتوبر 2026) حُذف: زرع بياناتٍ يدوي لمرة واحدة من أغسطس 2026، كود نقل القاعدة
  (`MIGRATE_FROM_*`؛ الفصل تمّ)، بقايا تبديل الحساب بين النسخ، ورسم الإيداع/السحب غير المستعمل.
